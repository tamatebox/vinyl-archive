# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Raspberry Pi audio capture server for archiving vinyl records: continuous line-in recording into a ring buffer of FLAC segments, silence-based session detection, and a web UI to save any detected session as a FLAC file. Python 3.11+, FastAPI, numpy/soundfile. See README.md for deployment and detector-tuning details.

## Commands

```sh
python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'   # setup
.venv/bin/pytest                                             # all tests (no audio hardware needed)
.venv/bin/pytest tests/test_detector.py -k test_name         # single test
VINYL_ARCHIVE_CONFIG=dev-config.toml .venv/bin/python -m vinyl_archive   # dev server
```

No linter/formatter is configured. Tests run at 8 kHz sample rate (conftest.py) to stay fast.

For end-to-end testing without ALSA hardware, override `[capture] command` in config with any command that writes raw S16_LE PCM to stdout — `tools/make_test_audio.sh` (requires ffmpeg) generates a silence/tone/gap pattern that exercises the detector.

## Deployment

`deploy/install.sh` does first-time setup (service user, venv, config seed, unit) then delegates to `deploy/update.sh`, which is also the update path (`git pull && sudo sh deploy/update.sh`) — so install and update cannot drift apart. update.sh stages the sources in a `mktemp -d`, *not* under `/opt/vinyl-archive`: the unit's `WorkingDirectory` is there and `python -m` puts the working directory first on `sys.path`, so a source copy beside the venv silently shadows the installed package. `PYTHONSAFEPATH=1` in the unit and in update.sh's own checks closes that hole for good — without it, checks run from the repo root inspect the checkout instead of what is installed. The pre-flight `import vinyl_archive.main` runs from `/` before the restart so a broken build or unparseable TOML is caught while the old version still serves; the post-restart health check polls `/api/status` and dumps `journalctl` on failure. Schema changes must stay backwards-compatible in `Database.__init__` (`CREATE TABLE IF NOT EXISTS` plus explicit `ALTER TABLE` for added columns, guarded by `PRAGMA table_info`) — `tests/test_upgrade.py` opens a pre-update database to prove an update needs no manual migration.

## Architecture

Everything is positioned by one **absolute sample counter** (frames since first capture, persisted across restarts via `db.max_end_sample()`). Segment filenames encode their start sample (`seg_<16-digit sample>_<ts>.flac`), sessions store start/end samples, and exports extract exact sample ranges. Wall-clock time is derived only for display, via an anchor in CaptureManager.

Data flow: subprocess source (`arecord` or config override) → `capture/recorder.py` reads PCM blocks → feeds both `ring/writer.py` (rotating 60 s FLAC segments + SQLite rows) and `sessions/detector.py` (hysteresis state machine; a session ends only after 25 s of continuous silence so track gaps never split a record side). With silence gating (`[capture] silence_gating`, default on) the recorder writes to disk only while a session is open: idle blocks sit in a RAM delay line sized to preroll+hold and are `skip()`ed in the writer — the sample counter advances over skipped audio, so gaps in segment coverage are normal and only ever lie outside sessions. The recorder gates on `gate_state()` (injected by the manager), not on the detector directly, so manual recordings write regardless of level.

Sessions have a `kind`: `auto` (detector — the always-on backup for a forgotten record button) or `manual` (`POST /api/record/start`). A manual take wins over detection: `CaptureManager.manual_start` adopts an in-progress auto session (keeping its preroll) or opens one at `position - preroll`, and while `_manual` is set the detector's callbacks do no DB bookkeeping; `manual_stop` closes it and re-arms the detector so backup coverage resumes at once. `GET /api/history` is the single user-facing timeline: unsaved sessions plus kept recordings, deduped (a saved session shows only as its recording) — one list, since the only real difference is whether an entry survives. It is rendered by two pages: `/` passes `?buffered_limit=N` (5, in `app.js`) plus `include_archived=false`, and `/history` passes nothing. The front page keeps buffered and kept in separate sections because they ask for different things — an entry in the buffer is a decision waiting to be made, a kept recording is the archive — and each is scoped its own way: a window over the buffer, and the kept entries not yet archived. Archiving (`recordings.archived_at`, `PATCH /api/recordings/{id}` with `{"archived": true}`) is purely about where an entry is listed: the row, the file and every audio route are untouched, which is why it needs no confirmation. It earns its place on the kept list and not on the buffered one because the kept list is unbounded while the buffered one is a fixed window — against a window, hiding a row could only pull an older row up into its place. Deleting is offered on `/history` and not on the front page, so the destructive action is not a mis-click away from the page in daily use. `/history` puts a month calendar over the same list, as an index rather than a separate view: with no day picked the list shows everything, so nothing is reachable only through the grid. Cells carry three states, not two — a day older than the buffer now reaches is not a day nothing was played — and the count is printed in the cell rather than encoded only as shading. The list below the grid holds the month on display, which is what makes month paging mean anything and bounds the list by a unit whose size does not depend on what the buffer happens to hold; paging clears a day selection, and is clamped to the range that has data. The page opens on the month of the newest entry, not blindly on the current one — capture can have been paused for weeks. All day bucketing is client-side (`localDayKey`): the server stores UTC and never guesses a timezone, so the browser is the only party that can say which day 23:40Z belongs to. How far back the buffer reaches is not a property of `max_segments` — it is playing time, so wall-clock span depends on how much gets played, which is why the history groups by day instead of assuming a span. That window is why no action hides an entry — the front page is a *recency window*, not a queue to be pruned, so an entry leaves it when newer ones arrive. A manual "dismiss" would be worse than absent: it never freed a byte (the ring reclaims that audio on its own schedule either way), it destroyed the only handle on buffered audio since every audio route is keyed by session id, and against a fixed-size window it could not even shorten the list — hiding one row pulls an older row up into its place. `tests/test_api.py::test_session_metadata_cannot_be_destroyed` pins that no route drops a session row. The limit also bounds server work, not just payload: `level_in_range` runs per returned session on every two-second poll.

Playback levelling (`sessions/loudness.py`) is **measurement at write time, gain at playback time**. `LevelMeter` accumulates two numbers over audio that is already in RAM — total energy (`mean_sq`) and the loudest 20 ms window (`short_peak`) — in the `SegmentWriter` per segment and in the `Exporter` per keeper, so `auto_gain_db` for a 25-minute side reads two DB columns instead of decoding the FLAC. `GET /api/history` reports the result as `gain_db` and the browser applies it with one Web Audio gain node per player (built lazily: the `<audio>` element is the one costly part of a row, so it is created by the Play button rather than up front — hundreds of rows of text are cheap, hundreds of media elements are not); nothing server-side scales a sample, so the archived file and the byte-offset arithmetic in `streamer.py` are both untouched. The ceiling is deliberately measured over a *window*, not the loudest sample: vinyl clicks mean true-peak normalisation would let one scratch veto the boost for a whole quiet side (`tests/test_loudness.py::test_a_single_click_does_not_hold_a_quiet_side_down` pins this — it was the first design's actual bug). Unmeasured rows read back NULL and play at unity, which covers both pre-upgrade databases and segments `reconcile` re-registered after a crash; `level_in_range` excludes them from the average rather than letting them drag it toward silence. Whole segments count even where a session only clips their edges — over-stating a level can only ask for less gain, never more.

Playback and download of a not-yet-kept session both go through `sessions/streamer.py`, in two shapes, because they want opposite things. Playback (`iter_range`) wraps buffer segments in a WAV header on the fly: byte offsets map arithmetically onto samples, which is what makes Range requests — hence seeking — work. Download (`iter_flac`) encodes to FLAC instead, since the archive format is what should land in the listener's hands; it is sequential, with no Content-Length and no Range, because a compressed stream has neither. Neither writes a temp file, so previewing and downloading cost no flash writes. Missing ranges are silence-filled so the stream matches the declared length.

Streaming FLAC works because libsndfile writes the stream strictly forward and only seeks back at `close()` to stamp frame count, frame sizes and MD5 into STREAMINFO — bytes a response has long since sent. `_FlacSink` therefore holds the header until it patches in the frame count, which is known up front from the sample range, and drops the close-time rewrite of already-sent bytes: unset frame sizes and an all-zero MD5 both mean "unknown" to a decoder (`flac -t` warns and passes), while duration — the field a player needs to show progress and seek — is the one we can fill ourselves. `tests/test_streamer.py` pins the two properties this rests on: bytes really do leave before the encode finishes, and the duration is right anyway. `SessionStreamer` and `Exporter` pin `config.audio` at construction because buffer segments are in the *running* format; `CaptureManager.status()`/`running_config()` report that rather than the configured one. Saving a session (`sessions/exporter.py`) streams the sample range out of buffer segments into `recordings/*.flac` — capture never pauses; output goes to a `.part` file renamed atomically.

Threading model:
- **capture-supervisor thread** (`capture/manager.py`): owns the writer, detector, and ring GC; restarts the source subprocess with backoff on EOF (device unplug/crash surfaces as pipe EOF — that's the whole failure-detection model, see `capture/source.py`). Most `SegmentWriter` methods are capture-thread-only; cross-thread requests go through `request_rotate()`/`flushed_end()`.
- **export pool** (single worker, `main.py`): runs exports; `Exporter` also holds its own lock.
- **FastAPI event loop**: API reads shared state; all handles live on `app.state`.
- `db.py` wraps one SQLite connection in an RLock (WAL mode); safe from all threads.

Key invariants:
- **Files are the source of truth.** `db.reconcile()` runs at startup and rebuilds/repairs DB rows from what's on disk (re-registers orphan segments, drops rows for missing files, force-closes sessions that were active at crash time — a restart implies a gap, so continuing them would be wrong).
- Session state machine: `active → ended → saving → saved`, with `expired` when the audio has left the buffer; only `ended` sessions are exportable, and a failed export reverts to `ended`.
- Ring GC (`ring/gc.py`, runs on every segment rotation, must never throw into the capture thread): deletes released segments after a grace period, enforces the segment cap, and protects segments overlapping unsaved sessions — evicting into one marks it `truncated_head`/`expired` rather than losing track silently. Saved recordings are never deleted automatically.
- Capture gaps are tracked explicitly (`discontinuity` flag on segments, `has_gaps` on recordings) rather than papered over.

Config (`config.py`) is frozen dataclasses loaded from TOML via `VINYL_ARCHIVE_CONFIG`; tests construct `Config(...)` directly with `tmp_path`. Audio format follows `[audio] bit_depth` (16 → int16/S16_LE, 24 → MSB-justified int32 unpacked from S24_3LE — the justification libsndfile uses for PCM_24 int I/O); `rms_dbfs` scales by dtype. `[paths] recordings_dir` optionally puts keepers on a separate volume from the DB and buffer.

`GET/PATCH /api/settings` edits the whitelist in `config.EDITABLE_SETTINGS` (bounds enforced by `validate_settings`); values persist in the DB `settings` table, which is merged over the TOML at startup *before* `reconcile` so the effective format is known. Detector tuning, gating and `device` apply live (`CaptureManager.apply_config`, `SilenceDetector.reconfigure`; a device change sets `_restart_source` to cycle the subprocess). Ring policy applies live too (`RingGC.reconfigure`, `SegmentWriter.set_segment_frames` — segments carry their own length in the DB, so mixed lengths need no special handling); `block_ms` cycles the source like `device`, since the recorder reads it once per run. Live-applied values are all derived from `_running_audio`, never the pending config, so a queued rate change cannot resize segments before the restart. The `RESTART_SETTINGS` (sample_rate, channels, bit_depth) cannot apply live — `restart_required()` reports them as pending, and on the next start `reconcile` discards buffer segments whose format no longer matches. Only four things stay file-only, and `tests/test_api.py::test_config_fields_are_classified` fails if a new config field is neither editable nor listed there: `[server]` host/port (a bad binding locks the UI out), `data_dir` (holds the settings store), `recordings_dir` (moving it orphans recordings that `reconcile` would then drop), and `capture.command` (argv from an unauthenticated UI is RCE). Bounds must not be stricter than what `Config.load` accepts, or a file-set value cannot be echoed back by `PATCH`. `[server] host`/`port` are honoured by the `python -m vinyl_archive` entry point (`__main__.py`, what the systemd unit runs) — it passes the app *object* built from the same config it read, so binding and serving can never disagree; invoking `uvicorn vinyl_archive.main:app` directly bypasses them and binds uvicorn's own defaults.
